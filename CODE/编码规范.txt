代码风格:
编写代码时，始终以所在文件的既有风格为基准。不要依赖通用编码规范，而是跟随项目自己的习惯。不要删除原本注释掉的代码。

修改前必读：（所有变量或者函数名禁止使用拼音）

代码尽量使用GB2312编码规范。
（因为我们需要大量使用oled屏幕，如果是UTF8的话显示汉字需要进行转换编码，我试了一下不是很方便，所以直接使用GB2312编码，如果使用vscode写代码记得更换默认编码格式）

一：命名以及注释规范
1.公共函数：模块小写前缀 + 下划线 + 功能名
2.内部辅助函数：模块前缀 + 功能名 + _ 尾部下划线
3.主入口函数：不带尾部下划线
4.typedef struct：结构体变量全大写下划线分隔，加项目前缀，枚举类型均大写
5.宏常量：全大写下划线，如MAX_LEN
6.变量：英文缩写或者英文拼写，英文单词之间用下划线分隔
7.指针变量：*紧挨变量类型 如：uint8*  p;
8.循环变量：int32（大范围）或 int8（小范围），直接在 for 语句中声明。(如果编译器不支持也可以在for循环外定义，因为旧的keil不支持在for语句中定义变量)
9.任何注释优先使用英文注释，发布版本时如面向大学生群体尽量用中午注释，如大型项目统一英文注释
10.每个开放函数均需要在.h文件中添加函数头注释，如只在当前.c文件中使用，在函数头添加简短注释

二：大括号风格
K&R 风格，左大括号与声明同行。所有 if/else/for/while/switch 都使用 {}，即使只有一条语句也要包含。else 独占一行。
void func(void) {
    if (cond) {
        do_something();
    }
    else {
        do_other();
    }
}

三：缩进与空行
4 空格缩进
函数之间空一行
函数内部大块逻辑之间空一行（内存分配后、大循环前后）
struct 定义内部不空行
变量声明必须逐行：即使是相同类型，每个变量也独立占一行

// 错误(禁止出现如下定义)
int32 head = 0, tail = 0;

// 正确
int32 head = 0;
int32 tail = 0;

四：内存管理
目前内存管理还是使用标准C库中的malloc、free函数，后续在新的firmware更换我们自己的内部内存管理函数。
尽量减少全局大数组的函数，全局函数变量前尽量加g_, 尽量减少全局变量的使用，后续新的版本的代码禁止随意定义全局变量。
（如果是为了少全局变量而少也没有必要，需根据实际情况自身定夺）

五：宏管理
尽量少的使用宏函数，除非对内存有需求，否则尽量少用宏函数

六：指针对齐检查
奇数地址访问风险：多个变量统一用 uint8* 申请内存，按 frame 宽度或高度偏移获取下一个指针位置。若偏移量为奇数，再强转为 int16*/int32*，将产生未对齐访问，在 ARM 等平台上崩溃或读取错误数据。
uint8 *buf = MEM_COMMIT(total_size);
int16 *p16 = (int16*)(buf + offset);   // offset 可能为奇数 → 未对齐！
int32 *p32 = (int32*)(buf + offset);   // offset 可能 %4 != 0 → 未对齐！
